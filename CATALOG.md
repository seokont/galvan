# Каталог Atelier

Каталог `/products` отримує імпортовані дані з NestJS, а не з демонстраційних JSON.
Головна сторінка отримує з того самого API до 10 різних колекцій, чергуючи
бренди. Картка показує назву колекції, бренд і фото товару цієї колекції
(окремі обкладинки колекцій в Odoo не заповнені). Посилання відкриває каталог
із вибраним брендом і колекцією. Службові категорії й категорії аксесуарів
не потрапляють до цієї добірки.
Дані завантажуються під час запиту без статичного кешу, тому наступне
відкриття головної відображає актуальний імпорт.
Потрібні запущені PostgreSQL, бекенд на порту 3001 та Next.js на порту 3000.

Із кореня проєкту у двох терміналах PowerShell:

```powershell
.\backend\dev.ps1
```

```powershell
.\frontend\dev.ps1
```

`BACKEND_URL` у `.env.local` фронтенду необов'язковий; типово це
`http://127.0.0.1:3001`. Шаблон: `.env.example`. Ключ Odoo та `DATABASE_URL`
не потрібно копіювати у фронтенд.

Фронтенд проксіює тільки GET-запити до дозволених шляхів `/api/catalog/*`.
Фільтри бренду, колекції, силуету й сторінка зберігаються в URL. Зміна бренду
скидає колекцію, а зміна фільтра — сторінку. Показується 24 товари на сторінку.
Фотографії, атрибути та розміри походять з імпорту; за відсутності фото
відображається заглушка. Старі адреси Galvan на кшталт `/products/g0001`
підтримуються, якщо відповідна модель входить до опублікованого імпорту.

Оновлення даних виконується окремо у `backend`: `npm run catalog:import`.
Дивіться `../backend/README.md`. Автоматичний розклад синхронізації
не налаштований. Форма контакту й клієнтська авторизація залишаються окремими задачами.

Адмінка: `/admin/login`. Редактор товарів і правила збереження ручних правок
описані в `../docs/ADMIN.md`.
